# 跨域配置修复 - 500错误解决

## 🔍 问题根源

**跨域配置冲突**导致500错误：
- ❌ Controller上有 `@CrossOrigin(origins = "*")`
- ❌ 又有全局 `CorsConfig` 配置
- ❌ 两者冲突导致Spring MVC处理异常

```java
@CrossOrigin(origins = "*")  // ❌ 与CorsConfig冲突

    // ...
}
```

### 修改后（正确）
```java

@RequestMapping("/api")  // ✅ 删除@CrossOrigin，统一使用CorsConfig
```

## 📊 跨域配置说明

### allowedOriginPatterns vs allowedOrigins

| 配置项 | 说明 | 是否支持通配符 |
|--------|------|---------------|
| allowedOrigins | 旧版本API | ❌ 不支持"*"与allowCredentials同时使用 |
| allowedOriginPatterns | 新版本API | ✅ 支持"*"与allowCredentials同时使用 |

### 为什么使用 allowedOriginPatterns？

```java
// ❌ 错误配置（Spring Boot 2.4+会报错）
.allowedOrigins("*")
.allowCredentials(true)

// ✅ 正确配置
.allowedOriginPatterns("*")
.allowCredentials(true)
```

## 🎯 为什么之前会500错误？

**可能的原因**：

1. **跨域配置冲突**
   - Controller级别的 `@CrossOrigin`
   - 全局的 `CorsConfig`
   - 两者处理逻辑冲突

2. **Spring版本兼容问题**
   - Spring Boot 3.x 对跨域配置更严格
   - `allowedOrigins("*")` 与 `allowCredentials(true)` 不能同时使用

3. **请求处理异常**
   - 跨域配置错误导致请求被拦截
   - 返回500错误
